# 聊天导入规范

决策依据：[ADR-0002](../adr/0002-message-revisions-and-evidence-references.md)、[ADR-0003](../adr/0003-confirmation-is-the-point-of-no-return-for-screenshots.md)。批次状态见 [state-machines](./state-machines.md)。

## 1. 统一消息结构
所属用户、对象、平台（微信/抖音/其他）、导入批次、发言人（我/对方/未确认）、内容、消息类型（文本/图片/语音/系统/其他）、**时间**与**时间精度**（秒/分/日期/仅顺序/未知）、顺序号、原始出处（批次+图片序号+区域，或文本行号）、识别状态（已识别/不确定/用户已改）、修订号。

## 2. 原则
- 不猜测：缺失的时间、看不清的文字、未提供内容的语音/图片，一律标"未知/不确定"，不补全。
- 无可靠时间 ⇒ 不计算回复间隔。
- 首次导入必须由用户确认"我/对方"，不得仅凭气泡颜色/位置决定。
- 用户可编辑所有识别文字；每次编辑产生新修订。

## 3. 导入流程
选择来源 → 上传或粘贴 → 识别整理 → 确认"我/对方" → 集中处理不确定内容 → 确认保存。
- 批内可交换发言人，交换前显示受影响的消息数与已有关联（如证据、重叠判定）。
- 上传、识别、确认进度存服务端；刷新后恢复；失败按项重试。
- 确认页明确提示：确认后原图将被删除，无法重新识别。

## 4. 重叠与重复
- **截图重叠**：相邻/相近截图的尾首若有连续的相同消息序列（内容+发言人，时间一致或未知），按序列匹配合并，而不是逐条按内容去重。
- **保留真实重复**：同一发言人连续发送相同内容（如连发两次"哈哈"），若不属于重叠序列，必须保留。
- **跨批次**：新批次与已确认消息比较，发现重叠序列时提示并默认合并，由用户确认；不得累计同一段聊天两次。
- **重复上传**：同一文件（哈希相同）重复上传提示并跳过。

## 5. 资料类型
用户可标记：**连续聊天** / **精选片段** / **不确定**。精选片段与不确定资料可支持具体表达分析，不得直接推断整段主动频率与稳定性（规则见评分文档 §3）。

## 6. 解析器扩展
文本/导出文件通过 `Parser` 接口接入：声明 `id`、`platform`、`detect(input)`、`parse(input)`。**只有存在明确格式说明与 `samples/` 测试样本的解析器才在界面中声明"支持"**，其余统一走"通用粘贴文本"（逐行启发式 + 必须用户确认发言人）。首批：通用粘贴文本（带 `samples/`）；微信/抖音导出文件格式在拿到真实格式样本后再声明。

## 7. 原图生命周期
确认后立即停止访问，24 小时内清理在线文件；未确认或失败的上传 7 天清理。分析引用整理后的消息及上下文，不依赖原图。
