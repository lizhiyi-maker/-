# 状态机

UI、API 与后台任务共用本文定义；状态枚举在代码中只有一处定义。术语见 [GLOSSARY](../../GLOSSARY.md)。

## 1. 导入批次
| 从 | 事件 | 到 | 说明 |
|---|---|---|---|
| — | 用户创建批次 | 上传中 | 选择来源与资料类型 |
| 上传中 | 文件/文本齐备，用户点"开始识别" | 识别中 | 预留识别额度 |
| 识别中 | 全部项成功 | 待确认 | |
| 识别中 | 部分项失败 | 识别中（等待处理失败项） | 成功的截图保留、不重跑；用户可只重试失败项，或跳过它们继续；处理完才整合并进入待确认（避免整合后又被重试打乱用户的编辑） |
| 待确认 | 用户确认保存 | 已确认 | **原图不可逆点**；触发原图清理任务 |
| 上传中/待确认 | 7 天未确认 | 已过期 | 清理文件 |
| 任意 | 用户删除 | 删除中 → 已删除 | 删除围栏，见 §5 |

粘贴文本跳过"识别中"，直接解析后进入待确认。

## 2. 截图识别（每个截图一项）
已上传 → 排队 → 运行中 → 已识别 / 失败；失败 → （重试）排队，或 → 已跳过。批次被删除时记录随批次删除，迟到的任务安静退出。
- 任务以“认领”方式执行：只有排队状态的截图能被认领，重复投递只处理一次。
- 额度以**轮**为单位：每轮预留本轮张数，结束后按成功张数结算、其余退还。失败项重试开新一轮。详见 [quota.md](./quota.md)。
- 批次状态：上传中 → （开始识别）识别中 → （全部结束且无失败项）待确认。识别中且有失败项时，批次停留在“识别中”，等待用户重试或跳过。

## 3. 分析任务
| 从 | 事件 | 到 |
|---|---|---|
| — | 用户点"开始分析"（需已同意 AI 服务说明） | 排队（预留分析额度） |
| 排队 | worker 取走 | 提取事实 |
| 提取事实 | 分段完成 | 维度解释 |
| 维度解释 | 完成 | 校验 |
| 校验 | 结构与引用通过 | 成功（结算额度，写入快照） |
| 校验 | 不通过 | 失败（系统失败，退还额度；可重试） |
| 任意 | 对象/用户被删除或输入被作废 | 已作废（丢弃结果，退还额度） |

## 4. 报告新鲜度
报告相对**当前**数据的状态，可同时满足多条时取下表优先级（上高下低）：

| 状态 | 触发 |
|---|---|
| 资料纠正已过期 | 报告引用的消息修订已被更新，或所属批次被删除 |
| 规则变更 | 规则版本升级 |
| 偏好变更待更新 | 偏好版本高于快照记录 |
| 有新资料待分析 | 存在快照之后确认的新批次或新线下事件 |
| 最新 | 以上均不满足 |

旧报告始终保留并注明"资料截止时间"。偏好/规则变更造成的分差展示为"口径变化"。

## 5. 删除围栏
1. 删除请求把目标标记为"删除中"并**同事务**提升其代际号；
2. 新任务提交时校验目标状态，拒绝；
3. 运行中任务写回前，在同一事务内对目标行加锁并校验"状态=正常且代际号未变"，否则丢弃并退还额度；
4. 异步清理派生数据与文件，完成后置"已删除"；
5. 备份、对象存储历史版本与外部服务留存**不属于**瞬时删除范围，见 [privacy-retention](./privacy-retention.md)。
