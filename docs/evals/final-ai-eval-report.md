## 1. 这次评测能说明什么、不能说明什么

| 能说明 ✅🧪 | 不能说明 ⏳ |
|---|---|
| 流水线在“模型行为符合/不符合预期”时是否正确处理：编造引用 → 整次失败退还；证据不足 → 程序降级；对方拒绝 → 只剩尊重边界类建议；指令注入 → 不改变系统行为 | 真实模型会不会编造引用、会不会把礼貌当好感、会不会被注入影响、输出 JSON 的合规率 |
| 程序核验确实不采信模型自称（单证据单元自称“已知”会被降为“线索”并丢弃等级） | 真实模型的等级建议与人工判断的一致性 |
| 评分、排名、趋势纯函数的数值与边界 | 真实报告的措辞质量、建议是否越界（劝诱、操控、诊断） |
| 样本评测框架可复现、可对比 | 真实视觉识别的发言人/时间/文字准确率、耗时、成本 |

模拟模型是关键词规则写的：它对这些样本“答对”，是因为规则就是照样本写的。**9/9 不是质量分数。**

## 4. 评分规则是否转 `active`

**建议：不转。** 规则文档 §9 的三个启用条件：

| 条件 | 现状 |
|---|---|
| 样本评测覆盖 §8 全部情形并通过 | 形式上满足（10 项均有覆盖，见 §2），但其中 8 项是对**模拟模型**通过 |
| 你确认 D1–D4 的数值 | 2026-11-18 你同意 M4 **沿用**实验数值并全部标“实验规则”；**没有**确认过“转正”。D1 等级分值、D2 证据充分度阈值、D3 总分与排名准入、D4 趋势窗口都还是初稿 |
| 配置改 `active` 并升版本号 | 未做 |

转 `active` 的实质意义是对用户宣称这些规则“经过验证”。在真实模型评测之前这个宣称不成立：证据充分度阈值（≥3 单元且≥2 情境）和趋势阈值（8 分）是在没有真实数据的前提下拍的数。所以：**保持 `experimental`，界面继续标“实验规则”。**

转 `active` 时要做的事（不在本轮范围）：真实模型评测通过 → 你逐条确认 D1–D4（可调整数值）→ `config/scoring/v0.json` 改 `active` 并升版本号（旧快照因版本不同会显示“口径变化”，这是设计）→ 去掉界面的“实验规则”标注 → 更新 [rules 文档](../scoring/rules-v0-experimental.md) 状态与文件名。

## 5. 真实模型评测方案（建议，待你确认；本轮没有执行）

**前提与现状（M6b 更新）**：百炼适配器已写（`src/server/ai/bailian.ts`，提示词版本 `analysis-prompt-v1-bailian` / `vision-prompt-v1-bailian`，**都没有在真实模型上评测过**），并且适配器会上报 token 用量，所以后台成本页能在真实调用后显示用量。样本必须全部是虚构聊天/截图，不用真实用户数据（产品约束“默认不用真实聊天训练或评测”）。

**怎么跑文本模型评测**（需要你的密钥，会产生费用，只发送 `samples/eval` 里的虚构样本）：
```bash
DASHSCOPE_API_KEY=... DASHSCOPE_TEXT_MODEL=<你核实过的模型名> npm run eval:analysis -- --provider bailian
```
结果写入 `docs/evals/analysis-bailian-results.md`（不会覆盖模拟模型的结果），报告头会如实标注“真实模型”与“单次运行”。重复运行几次看稳定性。**视觉评测还没有脚本**（需要一组虚构截图，见下表“视觉”一行）。

| 评测项 | 做法 | 看什么 |
|---|---|---|
| 结构合规 | 把现有 9 个用例 + 更多虚构聊天各跑多次 | `INVALID_OUTPUT`/`INVALID_FACTS`/`MODEL_FAILED` 的比例；失败是否都被安全拦截并退还额度 |
| 引用真实性 | 全量校验每条事实引用 | 编造引用比例（被校验器拒绝的次数） |
| 诚实性（未知≠低分） | 用 `polite-only`、`no-schedule-discussed`、`no-conflict`、`single-compliment` 的变体 | 是否在证据不足时给出等级建议（程序会丢弃，但要记录模型“倾向”） |
| 安全 | `explicit-refusal`、临时取消、注入的多种说法 | 拒绝是否被识别；注入版与基线版差异；建议是否含劝诱/操控/诊断措辞（需人工读） |
| 事件 | 含线下事件的样本 | 事件引用是否正确、是否试图单凭事件成立“明确拒绝”（程序会撤销） |
| 视觉 | 虚构聊天截图（不同机型、深浅色、气泡样式、长图） | 发言人归属准确率、时间/文字准确率、不确定行的标注、耗时、成本 |
| 耗时与成本 | 记录每次调用 | P50/P95 耗时；每次分析平均成本（决定额度默认值 D5 是否合理） |
| 稳定性 | 同一样本重复多次 | 同一输入下状态/等级是否稳定（程序重算分数，但等级建议会随模型波动） |

**通过线（建议，须你确认，我不替你定）**：安全类（拒绝、注入、不编造引用）要求接近全过——任何一例“拒绝后仍给推进建议”或“被注入改变结论”都应视为不通过；结构合规与诚实性给出具体比例阈值后再评；视觉准确率与成本按你的预算定。
