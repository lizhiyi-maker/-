# 产品方案（优化版）

本文是优化后的方案总览。细则见：[业务规范](./business/)、[评分规则](./scoring/rules-v0-experimental.md)、[术语表](../GLOSSARY.md)、[ADR](./adr/)、[待确认事项](./open-decisions.md)、[验证矩阵](./verification-matrix.md)。

## 1. 定位
面向中国大陆成年用户，帮助处于日常认识、了解、暧昧阶段的人整理互动资料、分析关系、比较发展适配程度。手机网页优先，兼顾电脑。邀请制免费内测，手机号验证码登录，按额度使用。

**评分含义**：这段互动与用户期待的适配程度；不是对人的评价，不是恋爱成功率预测。用户的"我的好感"独立展示，不参与评分。

**第一版不做**：AI 对话追问、回复草稿、自动发消息、支付订阅、原生 App、微信小程序。资料全部由用户主动上传。

## 2. 核心流程
新建对象 → 导入一批或多批资料 → 确认识别结果 → （可选）补充线下事件 → 用户点"开始分析" → 报告、评分、建议。
- 新增资料不自动触发分析，只显示"有新资料待分析"；旧报告保留并注明资料截止时间。
- 确认导入后提供"继续添加资料"与"开始分析"。
- 截图识别与关系分析是两个独立后台任务；离开页面继续运行，刷新可恢复进度。

## 3. 对象与偏好
- 创建对象仅昵称/代号必填；选填性别、认识渠道、大概认识时间、关系阶段、个人感受与期待。支持男/女/全部列表；未填性别也能正常管理。
- 阶段：刚认识、正在了解、已确认关系、已结束（用户确认，AI 只建议）。见面经历与"是否暧昧"单独记录。
- 同一对象可关联多个平台账号，由用户确认；AI 提取的档案信息标来源并待确认。
- 偏好：当前关系期待、联系频率、推进节奏、维度重要程度；可跳过使用公开默认配置；全对象统一；修改后旧分析标记待更新。
- "我的好感"（还不确定/想继续了解/很心动/暂时不想继续）独立填写并保留修改历史。已确认关系、已结束退出发展排名，仍可查看。

## 4. 导入、分析、评分
详见 [导入规范](./business/import-spec.md)、[分析规范](./business/analysis-spec.md)、[评分规则](./scoring/rules-v0-experimental.md)。要点：不猜测缺失时间与看不清的内容；"资料不足"是独立状态；AI 给等级与证据、程序算分；证据必须可回查；聊天内指令一律视为资料；明确拒绝即停止推进建议。

## 5. 对比
同阶段且证据覆盖可比才排序，同分并列；跨阶段只展示维度、证据、阶段、个人好感，不给统一名次。手机一次比两人，电脑最多三人。

## 6. 账户、隐私、额度、后台
见 [隐私与保留](./business/privacy-retention.md)、[额度](./business/quota.md)。后台含邀请码、用户状态、额度调整、任务状态、成本、反馈、审计；管理员默认不浏览完整聊天。

## 7. 技术栈
Next.js + TypeScript + Tailwind CSS + shadcn/ui + Lucide；PostgreSQL + Prisma；pg-boss 独立 worker（其内部表由 pg-boss 迁移，不入 Prisma）；Zod 校验输入与 AI 结构化输出。
生产候选：阿里云中国大陆地域、Docker、托管 PostgreSQL、OSS 私有存储、国内短信；AI 优先评估百炼通义千问视觉与文本模型，通过中文模拟样本比较质量/耗时/成本后定型；封装为可替换接口，第一版只接一家。
本地：`embedded-postgres`（无 Docker 时）、模拟模型、开发登录、本地模拟存储，界面显著标注演示状态；**生产环境启动时若检测到演示开关则拒绝启动**。

## 5′ 在原方案上的优化点（摘要）
1. 显式状态机（批次/识别/分析/报告新鲜度）；2. 消息修订 + 证据引用；3. 同意前移到"首次发送任何内容给 AI 服务商"；4. 确认=原图不可逆点；5. 删除围栏；6. 额度预留/结算/退还账本；7. 评分管线分层（AI 等级 + 纯函数计分）；8. 验证状态矩阵；9. AI 评测的诚实边界。

## 6′ 移动端体验
手机底部导航：对象、对比、记录、我的；对象详情：概览、聊天资料、分析与建议、关系记录。电脑：侧边导航、宽布局。首页突出待确认与待分析。覆盖上传、空数据、失败、重试、超额、过期分析、删除状态。目标环境：iPhone Safari、Android Chrome、微信内置浏览器（真机验证由你完成，见验证矩阵）。

## 7′ 实施顺序
Stage 0 文档 → M0 脚手架 → M1 账户与档案 → M2 导入与纠错 → M3 分析与报告 → M4 评分与对比 → M5 手机端与部署验收。权限、删除、额度随各阶段实现；每阶段交付可运行成果与验证结果，阶段间等你验收。

## 8. Skill
使用：domain-modeling（术语与 ADR）、prototype（M2 确认页、M4 对比页）、tdd（权限/导入/额度/评分）、code-review（阶段结束，需 git 基线）。项目专用 Skill（聊天导入、关系分析、评分规则、AI 接入与评测、部署与数据管理）位于 `.claude/skills/`，只引用本目录文档与 `config/`，不复制规则。
