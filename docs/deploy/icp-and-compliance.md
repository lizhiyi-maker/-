# 备案与合规核实清单

> **这不是法律意见，也不是备案操作手册。** 我无法联网核实各部门当前的规则、时限和材料要求，下面凡是“规则/流程/时长”的内容一律标 **待核实**，须由你、法务或阿里云备案客服确认后才能据此行动或写进用户界面。本文的价值是：把**产品实际做了什么、没做什么**说清楚，让核实的人有的放矢。
> 相关设计：[隐私、保留与删除](../business/privacy-retention.md)（§5 是合规核实清单的出处）、[验证矩阵](../verification-matrix.md)。

## 1. 产品事实（核实人需要知道的）

| 事项 | 事实 |
|---|---|
| 服务对象 | 受邀内测用户（邀请码注册，手机号验证码登录）；尚未对公众开放 |
| 处理的数据 | 手机号；用户录入的**他人**的昵称与阶段；聊天文本/截图（含对方的话语与可能的个人信息）；线下事件事实；用户本人的好感与个人感受 |
| 敏感性 | 聊天内容可能含敏感个人信息（情感、行踪、健康、财务等），且**主要是第三方（对方）的信息**——对方并未同意被处理 |
| 发给第三方 | 截图 → AI 视觉服务；整理后的聊天事实与线下事件事实 → AI 文本服务（候选：阿里云百炼）。**个人感受不发送**。手机号 → 短信服务 |
| 同意 | 首次发送前必须勾选并记录 AI 服务同意（按文案版本+服务商）；文案如实写明“服务商留存条件尚未核实，不作承诺”。**粘贴文本导入不发送给 AI**，不受该关卡约束 |
| 用户权利 | 导出（JSON + 聊天文本）、单批/对象/账户删除（账户删除=立即停用+立即删除在线数据）。**未做**：更正他人信息的申诉渠道、对方（非用户）行使权利的入口 |
| 不做的事 | 不展示成功概率/百分比；不做心理诊断；明确拒绝后停止追求类建议；默认不用真实聊天训练或评测产品；评测只用虚构样本 |
| 数据位置 | 计划放阿里云中国大陆地域；**尚未部署**，没有任何真实用户数据 |
| 年龄 | 没有成年人确认机制（当前只有邀请码 + 手机号）；**待核实**需要什么方式 |

## 3. 备案与上线的大致顺序（通用流程，细节待核实）

1. 确定主体（个人/企业）与域名；域名需已实名。
2. 购买中国大陆地域云服务（备案通常要求关联服务器/接入商——**待核实**）。
3. 在阿里云备案系统提交主体与网站信息，等待初审与管局审核（**时长因省份而异，待核实**）。备案期间网站通常不能对公网开放（**待核实**）。
4. 备案通过后，把备案号显示在页面底部（要求以管局为准）——**当前页面没有备案号位置**，需要时再加（会改动界面，须先确认）。
5. 并行：短信签名与模板审核、隐私政策与协议、法务核实 C4–C11。
6. 全部通过后才能走 [部署指南](./README.md) §7 的上线前检查。

## 4. 产品已具备、可作为合规材料基础的能力（✅/🧪）

- 首次向 AI 服务商发送前的单独同意与记录（✅，集成测试：未同意不能开始识别/分析）。
- 导出与账户删除（✅，集成测试 + 三种视口 e2e）。
- 管理员默认看不到聊天内容；后台任务/成本/反馈页不含内容；审计不含内容（✅）。
- 手机号 HMAC 索引 + 应用层加密、验证码只存哈希（✅）。
- 生产环境拒绝演示/模拟配置（✅）。

## 5. 产品暂不具备（上线前需要决定是否补）

- 隐私政策、用户协议、备案号展示位置、上传他人聊天的权利提示（C8、C12）。
- 成年人确认（C7）。
- 备份中已删除数据的重放工具（见 [limitations](../limitations.md)）。
- 对方（非用户）的更正/删除申诉渠道。
